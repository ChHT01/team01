# Обучение распознаванию банок: синие, розовые, зелёные и брак

Комплект дообучает YOLO11n-cls на ваших изображениях и сохраняет `best.pt`. Камера, `motion.core`, SmartCamera и подключение к роботу для обучения не нужны. Это классификация одной банки на снимке или в вырезанной области ROI, а не поиск нескольких банок в кадре.

## Что именно распознаётся

- **blue**: синяя банка без размеченного дефекта.
- **pink**: розовая банка без размеченного дефекта.
- **green_white**: зелёная / зелёно-белая банка без размеченного дефекта.
- **defect**: банка с дефектом любого цвета.

Ответ один из четырёх: при таком устройстве классов дефект заменяет цвет. Чтобы одновременно получать цвет и наличие брака, нужна другая разметка и схема модели. Руки, пустые ячейки и посторонние предметы в эти четыре класса не входят.

В YOLO11 есть предобученные классификационные веса `yolo11n-cls.pt`; Python API позволяет дообучать модель методом `train`: [официальная документация YOLO11](https://docs.ultralytics.com/models/yolo11).

## Содержимое комплекта

- **prepare_dataset.py**: разделение исходной папки на `train` и `val` по группам исходников или сцен, либо подключение отдельной валидационной выборки.
- **train_jars.py**: проверка данных, обучение, сохранение лучших весов и оценка по каждому классу.
- **jar_model.py**: одинаковая обработка изображений для обучения и проверки. Изображение вписывается целиком в квадрат с серыми полями, без обрезки и искажения пропорций.
- **predict_image.py**: проверка отдельного фото и класс `JarClassifier` для дальнейшего использования с OpenCV.
- **dataset_utils.py**: поиск повреждённых файлов и некоторых видов утечки данных.
- **test_dataset.py**: автоматические тесты разделения и проверки.
- **requirements.txt**: зависимости.

Все `.py` оставьте в одной папке. В обученных весах сохраняется ссылка на преобразование `jar_model.FullImageSquare`, поэтому при переносе весов на другой компьютер переносите весь комплект, а не только `best.pt`.

## Установка

Рекомендуется отдельное окружение Python 3.11. Не устанавливайте зависимости в рабочее окружение управления роботом: так обновление PyTorch/OpenCV не затронет существующий код камеры.

### Windows

Откройте командную строку в папке с файлами и выполните:

```bat
py -3.11 -m venv .venv
.venv\Scripts\activate
python -m pip install --upgrade pip
python -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu
python -m pip install -r requirements.txt
```

Это вариант для процессора. Для NVIDIA вместо строки установки CPU-версии установите PyTorch с подходящей CUDA, выбрав конфигурацию в [официальном установщике PyTorch](https://pytorch.org/get-started/locally/), затем установите `requirements.txt`.

### Linux

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install --upgrade pip
python -m pip install torch torchvision --index-url https://download.pytorch.org/whl/cpu
python -m pip install -r requirements.txt
```

При первом запуске модель скачивает предобученные веса. Для автономного компьютера заранее положите `yolo11n-cls.pt` рядом со скриптом или укажите локальный путь через `--model`; после установки зависимостей и загрузки весов камера для обучения не нужна.

## Подготовка вашего датасета

### Если используется ранее подготовленный архив из 700 изображений

Распакуйте его рядом со скриптами. Ожидается структура:

```text
jar_training/
├── train_jars.py
├── prepare_dataset.py
├── jar_model.py
├── dataset_utils.py
├── predict_image.py
└── jar_dataset_700/
    ├── manifest.csv
    └── dataset/
        ├── blue/
        ├── defect/
        ├── green_white/
        └── pink/
```

Подготовьте выборки:

```bash
python prepare_dataset.py --raw jar_dataset_700/dataset --out dataset_ready
```

Скрипт автоматически найдёт `jar_dataset_700/manifest.csv` и разделит данные по `scene_group`, а не по отдельным вариантам снимков. На проверенной копии архива получено 529 обучающих и 171 валидационное изображение; три сцены попали в обучение, одна в проверку.

Это только техническая валидация по отложенной сцене. В архиве 700 изображений получены из 24 исходных снимков, а физические банки могут повторяться в разных сценах; такое разделение не доказывает качество на новых партиях. Разметка `defect` в исходном архиве предварительная, её необходимо проверить по вашим критериям брака.

Исходные изображения не удаляются и не меняются. Если `dataset_ready` уже существует, скрипт остановится: повторно используйте готовую папку либо укажите новый `--out`.

### Предпочтительный вариант: отдельные новые снимки для валидации

Снимите другие физические банки в отдельной съёмочной сессии с рабочей камеры и разместите по тем же четырём папкам внутри `new_validation`. Тогда все 700 подготовленных изображений можно использовать для обучения:

```bash
python prepare_dataset.py --raw jar_dataset_700/dataset --val-raw new_validation --out dataset_real_validation
python train_jars.py --data dataset_real_validation --epochs 100 --batch 16 --device cpu
```

Внешняя валидация считается независимой по вашему указанию; программа не умеет надёжно определять, что на разных снимках одна и та же физическая банка. Если внешние файлы содержат `srcNN`, эти номера должны обозначать исходники глобально, а не начинаться заново в каждой папке.

### Если у вас другой датасет

Для обычной папки с четырьмя классами:

```text
my_dataset/
├── blue/
├── defect/
├── green_white/
└── pink/
```

Если каждый файл действительно независим, без вариантов одного исходника и повторов тех же банок, можно явно разрешить разделение по файлам:

```bash
python prepare_dataset.py --raw my_dataset --out dataset_ready --independent-images
```

Не используйте этот флаг для аугментированного набора. Для такого набора задайте CSV с `image_path,class,scene_group` и `--manifest path/to/manifest.csv`; пути `image_path` должны быть относительно CSV. Альтернатива: без CSV скрипт понимает окончания имён вида `_src07.jpg`, группируя варианты по номеру исходника.

Если папки `train/val` уже подготовлены, этот шаг пропускается:

```text
dataset_ready/
├── train/
│   ├── blue/
│   ├── defect/
│   ├── green_white/
│   └── pink/
└── val/
    ├── blue/
    ├── defect/
    ├── green_white/
    └── pink/
```

Папка `test` с теми же классами необязательна и предназначена для отдельной итоговой проверки. Такая организация по классам соответствует формату [датасетов классификации Ultralytics](https://docs.ultralytics.com/datasets/classify/).

Вариант с `data.yaml` и рамками объектов относится к детекции. Этот комплект такую разметку не использует: для нескольких банок в одном кадре нужна модель детекции либо заранее известные отдельные ROI.

## Обучение

Сначала можно проверить датасет без скачивания весов:

```bash
python train_jars.py --data dataset_ready --check-only
```

На процессоре:

```bash
python train_jars.py --data dataset_ready --epochs 100 --batch 16 --imgsz 256 --device cpu
```

На первой NVIDIA с доступной CUDA:

```bash
python train_jars.py --data dataset_ready --epochs 100 --batch 16 --imgsz 256 --device 0
```

Если `--device` не указан, скрипт выбирает NVIDIA при доступной CUDA, иначе CPU. При нехватке памяти уменьшите `--batch` до 8 или 4; `--workers 0` оставлен по умолчанию для более простого запуска, в том числе на Windows.

Максимум по умолчанию 100 эпох, ранняя остановка после 20 эпох без улучшения. Это начальные параметры для эксперимента, не обещание требуемой точности; исходный набор уже содержит аугментации, поэтому дополнительные случайные изменения оттенка, стирание участков и обрезка в этом комплекте отключены.

Стандартные преобразования классификатора включают случайную/центральную обрезку; здесь они заменены обработкой всего изображения, чтобы не удалять область дефекта: [документация классификации и примеры собственного Trainer](https://docs.ultralytics.com/tasks/classify/).

## Где результат

Каждый новый запуск создаёт отдельную папку:

```text
runs_jars/jars_YYYYMMDD_HHMMSS/
├── weights/
│   ├── best.pt
│   └── last.pt
├── results.csv
├── results.png
├── args.yaml
├── training_summary.json
└── evaluation_val/
    ├── confusion_matrix.png
    └── confusion_matrix_normalized.png
```

В конце скрипт печатает точный абсолютный путь `best.pt`. В `training_summary.json` сохраняются соответствие номеров классам, версии библиотек, top-1 accuracy, precision, recall и F1 для каждого класса; наличие `test` добавит отдельную итоговую оценку.

Для брака особенно проверяйте `metrics.val.per_class.defect.recall`: какая доля размеченных дефектных банок найдена. Смотрите и precision этого класса, чтобы понимать количество ложного брака; при этом ошибки исходной разметки делают любые метрики недостоверными.

Ultralytics также выводит top-5 accuracy. При четырёх классах она неинформативна, поэтому ориентируйтесь на top-1 и показатели отдельных классов; [документация метрик классификации](https://docs.ultralytics.com/tasks/classify/).

Возобновление прерванного обучения, если `last.pt` успел сохраниться:

```bash
python train_jars.py --data dataset_ready --resume runs_jars/jars_YYYYMMDD_HHMMSS/weights/last.pt --device cpu
```

Замените пример пути фактическим. `resume` использует настройки исходного запуска, включая число эпох; завершённый и очищенный от оптимизатора checkpoint может не поддерживать продолжение, тогда начинайте новый запуск через `--model путь/к/best.pt`.

## Проверка фотографии

```bash
python predict_image.py --weights runs_jars/jars_YYYYMMDD_HHMMSS/weights/best.pt --image test_jar.jpg
```

Команда выводит JSON с выбранным классом, русским названием, уверенностью и оценками всех четырёх классов. Порог 0.75 является стартовой эвристикой: значение softmax не следует считать откалиброванной вероятностью правильного ответа.

Ниже порога возвращается `unknown`. Однако пустой фон, рука и новый тип брака могут получить высокий балл известного класса: порог не заменяет обучение на таких примерах и не гарантирует обнаружение незнакомых объектов.

## Дальнейшее использование с вашим кодом камеры

В модуле `predict_image.py` есть готовый метод `JarClassifier.predict_bgr(roi)`, принимающий вырезку OpenCV. Для камеры следует брать чистый кадр до нанесения `cv2.putText`, вырезать область одной банки внутри рабочей зоны и только её передавать классификатору.

Не подавайте полный кадр с несколькими банками: один ответ не описывает все объекты. Существующий `getPerson()` остаётся отдельной функцией; модель не обучается определять руку, не управляет ARM95 и не является системой безопасности.

Код подключения к SmartCamera намеренно не менялся: задача этого комплекта только обучение и проверка модели. Установка модели на самом устройстве камеры здесь не реализована, инференс рассчитан на компьютер с Python.

## Проверка комплекта

```bash
python -m unittest -v test_dataset
```

При подготовке комплекта выполнены тесты проверки данных, разделение реального архива, пробное обучение на CPU в одну эпоху при размере 64 × 64, сохранение/повторная загрузка весов и распознавание отдельного изображения. Это проверка исполняемости, а не полноценное обучение или оценка производственного качества.

Проверенное окружение: Python 3.11.15, Ultralytics 8.4.171, PyTorch 2.14.1+cpu, torchvision 0.29.1+cpu. Для основного обучения используйте размер 256 из команд выше; пробные веса и исходный датасет в архив кода не включены.

При коммерческом внедрении отдельно проверьте применимость условий лицензии Ultralytics к вашему проекту. Не считайте наличие рабочего кода подтверждением лицензирования промышленного продукта.
