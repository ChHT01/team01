# Распознавание банок на сетке 3×3

Полный модуль для существующей модели `best.pt` и SmartCamera `192.168.2.110`. Анализируются девять отдельных ячеек исходного поля; команды движения ARM95 не отправляются, код обучения и веса не изменяются.

## Как устроена обработка

1. Оператор отмечает четыре внешних угла поля в изображении камеры.
2. Программа выпрямляет выбранный четырёхугольник и делит его на 3×3.
3. Оператор убирает все предметы и сохраняет эталон пустого поля клавишей B.
4. Сравнение с эталоном оценивает наличие объекта в каждой ячейке. Это отдельная эвристика, а не обученный класс «пусто».
5. Для занятой ячейки выделяется изменившаяся область, добавляется небольшой отступ, затем вырезка передаётся вашему классификатору.
6. Подтверждённый ответ появляется после трёх одинаковых последовательных результатов. При движении или сигнале `getPerson()=1` распознавание временно приостанавливается.

Предполагается не более одной банки в каждой ячейке и фиксированная камера. Предметы за пределами выбранного четырёхугольника изображения не входят в анализ; сортировочные коробки не нужно включать в выбранную область.

Это не детектор, находящий произвольные банки во всём изображении. Четыре класса модели остались прежними: `blue`, `pink`, `green_white`, `defect`; для дефектной банки цвет отдельно не определяется.

## Какие файлы перенести

Распакуйте архив и скопируйте содержимое папки `jar_grid_3x3` в вашу существующую папку:

```text
AI/jar_training/
```

Файлы модуля:

```text
camera_grid_3x3.py       главный запуск
grid_core.py             геометрия, фон, фильтрация, сохранение
smart_input.py           адаптер получения кадров
jar_model.py             совместимость с преобразованиями ваших весов
test_grid.py             тесты без камеры
README_GRID_RU.md         эта инструкция
```

`jar_model.py` совпадает с файлом исходного комплекта обучения. Если он уже существует и вы его не меняли, можно оставить существующий; остальные файлы новые. Не удаляйте `runs_jars`, `dataset_ready`, `my_dataset`, `pyproject.toml` и `.venv`.

Веса в этот архив не включены: используются ваши уже обученные. Пакеты заново устанавливать по умолчанию не нужно, поскольку обучение и распознавание фото у вас уже запускались; для реальной камеры необходима библиотека `motion.core` из вашего рабочего проекта.

## Запуск с вашей камерой

Откройте терминал в `AI/jar_training` и выполните:

```bash
uv run python camera_grid_3x3.py --weights runs_jars/jars_20261001_163317/weights/best.pt --ip 192.168.2.110
```

Это путь к весам основного обучения, а не первого пробного запуска `161544`. Если используете другую папку обучения, замените путь после `--weights`.

Работайте в локальной графической сессии Linux, не в терминале без рабочего стола. Требуется рабочий OpenCV с оконным интерфейсом; при ошибке `imshow`/Qt не переустанавливайте пакеты вслепую, сохраните полный текст ошибки.

## Первый запуск: настройка сетки

В окне `Robot camera - calibration` появится изображение. Последовательно нажмите левой кнопкой мыши:

1. Верхний левый угол внешней границы поля.
2. Верхний правый.
3. Нижний правый.
4. Нижний левый.

Нажмите Enter, чтобы принять точки. Если ошиблись, нажмите R и выберите все четыре точки заново. Во время выбора показан замороженный кадр; C берёт новый кадр для повторной настройки.

Выбирайте только исходную рабочую сетку, без приёмных коробок. Внутренние линии делятся на равные трети после перспективного преобразования; проверьте, что наложенные границы совпадают с реальными ячейками.

Нумерация на экране:

```text
1  2  3
4  5  6
7  8  9
```

Это нумерация изображения, а не подтверждённая привязка к координатам робота. Если физическая схема I–IX имеет другой порядок, не используйте номера для команд манипулятору без отдельной проверки соответствия.

### Сохранение пустого поля

Уберите все банки, руки и другие предметы из сетки. Убедитесь, что камера, поле и освещение неподвижны, подождите примерно две секунды, нажмите B при фокусе на одном из окон OpenCV.

Программа проверит неподвижность последних 15 кадров и сохранит фон. Нажатие B является вашим подтверждением, что поле пустое; сама программа не может это доказать, особенно если `getPerson()` недоступен.

Если сохранить фон с банками, они могут затем ошибочно считаться пустым фоном. Исправление: убрать банки и повторить B, не меняя положение камеры.

После этого разместите банки по центрам ячеек. Часть ячеек может оставаться пустой; устойчивые ответы появляются после трёх анализов, интервал по умолчанию 0,4 секунды.

## Окна и клавиши

- **Окно камеры:** исходное изображение, внешние границы ячеек, номера и состояние сигнала человека.
- **Окно Jars 3x3:** выпрямленное поле с результатами для каждой ячейки.
- **C:** заново выбрать четыре угла; прежний фон для новой геометрии не используется.
- **R:** очистить точки во время выбора.
- **Enter:** принять четыре точки.
- **B:** запомнить неподвижное ПУСТОЕ поле.
- **S:** сохранить последний проанализированный кадр, девять чистых вырезок, изображение с результатами и JSON.
- **Q или Esc:** выйти.

Нажимайте клавиши в английской раскладке, при активном окне OpenCV. Исходный кадр не изменяется надписями перед подачей модели.

Калибровка сохраняется в `grid_3x3_calibration.npz` рядом с программой и загружается при следующем запуске. Если камера сдвинулась, наклонилась, изменился зум или освещение, старый файл может быть непригоден даже при прежнем разрешении: повторите C и B.

## Что означают надписи

| Надпись | Значение и действие |
|---|---|
| BLUE | Синяя банка по ответу модели. |
| PINK | Розовая банка по ответу модели. |
| GREEN | Зелёная / зелёно-белая банка по ответу модели. |
| DEFECT | Предполагаемый дефект по ответу модели, не подтверждение оператора. |
| EMPTY | Изменений относительно пустого эталона мало. Это оценка, не гарантия отсутствия предмета. |
| UNKNOWN | Уверенность модели ниже порога. |
| WAIT | Ответ ещё не повторился три раза подряд. |
| CHECK OCCUPANCY | Изменений недостаточно для уверенного решения «пусто/занято». |
| MOVE TO CENTER | Изменившаяся область касается края внутренней ROI. Переместите банку ближе к центру или проверьте сетку. |
| MOTION | Сцена изменяется. Уберите руку и дождитесь неподвижности. |
| PERSON SIGNAL | SmartCamera.getPerson() вернул положительный сигнал. |
| PERSON UNKNOWN | Сигнал getPerson недоступен/ошибочен. Это НЕ означает отсутствие руки. |
| SCENE CHANGED | Сильно изменилось почти всё поле. Проверьте камеру/свет и заново снимите пустой фон. |
| NO FRAME | Не получен корректный кадр; предыдущие результаты сброшены. |
| SET EMPTY GRID: B | Ещё нет эталона пустой сетки. |

Показатель `score` является оценкой модели, а не откалиброванной вероятностью правильного ответа. Рука, упаковка другого вида и неизвестный дефект могут получить высокий score известного класса; `getPerson()` и контроль движения лишь дополнительные сигналы, не защита от всех таких случаев.

## Проверка без камеры

На фото всей сетки:

```bash
uv run python camera_grid_3x3.py --weights runs_jars/jars_20261001_163317/weights/best.pt --image grid_with_jars.png --empty-image grid_empty.png --calibration photo_grid.npz
```

Оба фото должны иметь одинаковое разрешение, ракурс и освещение; `grid_empty.png` должно показывать действительно пустое поле. При первом запуске отметьте углы и нажмите Enter: эталон будет взят из `--empty-image`; если калибровка уже загружена, для применения нового `--empty-image` нажмите C и подтвердите углы заново.

Для USB-камеры вместо SmartCamera:

```bash
uv run python camera_grid_3x3.py --weights runs_jars/jars_20261001_163317/weights/best.pt --video 0 --calibration usb_grid.npz
```

Для заранее записанного видео можно указать путь после `--video`. Убедитесь, что в начале есть пустой неподвижный кадр для B, либо подготовьте `--empty-image`; видео идёт с частотой цикла программы, не предназначено для точного воспроизведения по временным меткам.

## Настройка под реальное изображение

Начните с параметров по умолчанию. Меняйте только один параметр за раз, сохраняя примеры клавишей S.

- **Слабые изменения света считаются банкой:** сначала зафиксируйте свет и обновите пустой фон. Затем, при необходимости, увеличьте `--diff 25` до `--diff 35`; это снижает чувствительность и может скрыть малоконтрастные банки.
- **Маленькая банка не считается занятой ячейкой:** после проверки сетки можно уменьшить `--occupied-ratio 0.08` до `--occupied-ratio 0.05`. Доля задаётся относительно внутренней области ячейки, не всего кадра.
- **Много неопределённых ответов:** проверьте вырезки и разметку. Не снижайте порог уверенности только ради исчезновения UNKNOWN.
- **Банка обрезается:** сначала исправьте четыре угла или расположение предмета. `--margin 0.04` убирает по 4% с каждой стороны ячейки; можно уменьшить отступ, но границы соседних ячеек не должны попадать в одну вырезку.
- **Медленная обработка:** увеличьте `--interval 0.4` до `--interval 0.8`. `--fps 15` задаёт целевую частоту, а не гарантию: скорость ограничена камерой и вычислениями.

Гомография описывает одну плоскость. При сильном боковом ракурсе, высоких банках, перекрытиях и заметном параллаксе четырёх углов поля может быть недостаточно: надо менять ракурс/выбирать плоскость верхов банок или настраивать индивидуальные ROI. Нельзя исправить перекрытие объектов простым увеличением числа эпох.

## Сохранённые результаты

После S создаётся отдельная папка в `grid_snapshots`:

```text
grid_snapshots/дата_время/
├── frame.png
├── grid_clean.png
├── grid_result.png
├── cell_01.png
├── ...
├── cell_09.png
└── results.json
```

Кадр и JSON относятся к одному последнему проанализированному изображению, а не обязательно к моменту нажатия клавиши. В JSON есть номера/строки/столбцы ячеек, состояния, score и признак устойчивости; `empty` и `unknown` являются состояниями программы, не дополнительными обученными классами.

Чистые вырезки полезны для проверки и последующего дообучения на реальной камере. Не переносите их в обучающие классы автоматически по предсказанию: сначала подтвердите истинную метку вручную.

## Проверки и ограничения

Автоматические тесты без подключения камеры:

```bash
uv run python -m unittest -v test_grid
```

Пройдены 16 автоматических тестов: геометрия и нумерация, исключение внешней области, пустой фон, движение, девять занятых ячеек, контроль края, устойчивость, сериализация калибровки, сохранение результатов и форматы кадров. Последовательность выбора углов, записи фона и сохранения результата проверена с подставным источником кадров и заменёнными оконными функциями, не на физическом дисплее. Отдельно выполнена загрузка ранее созданных тестовых весов и пакетный инференс девяти изображений.

Фактическое подключение к вашей SmartCamera и качество на живой сетке в среде подготовки кода не проверены. Адаптер использует список методов из вашего исходного скрипта и печатает выбранный метод; при несовместимости API он выводит диагностические сообщения, а не подставляет выдуманный RTSP-адрес.

Если точный метод известен, его можно указать через `--frame-method getImage` (замените `getImage` действительным именем). NumPy-кадры считаются BGR uint8, как в исходном OpenCV-коде; если SDK возвращает RGB-массив, понадобится явное преобразование в адаптере.

Если SDK постоянно возвращает старый закэшированный кадр или блокируется внутри вызова, данный модуль не может достоверно определить свежесть кадра без меток времени/счётчика кадров от SDK. Обработка выполняется в одном процессе, таймаут относится к возвращаемым отсутствующим кадрам, а не прерывает зависший вызов SDK.

Модуль не управляет роботом и не заменяет аппаратные блокировки, ограждения или сертифицированную защиту. Перед внедрением проверьте каждую ячейку на новых годных/дефектных банках, пустом поле, появлении руки, изменении света и потере камеры.
